# 设计规范「案头」

> 本文件受保护。执行者只能遵守，不能修改。发现规范没覆盖到的情况，先在任务单里写阻塞记录，交项目所有者决定。

## 1. 概念

一张摊在案头的纸。用户用**朱笔**批示，AI 用**铅笔**写建议，**盖了朱印的才是定论**。

产品最独特的能力是"区分 AI 建议与用户确认"，所以视觉语言就围绕这一点建立。界面里每一种颜色、每一种线条，都在回答"这是谁写的、算不算数"。

三个关键词：**安静、方正、有分量**。
- 安静：大面积暖白纸色，没有渐变，没有彩色色块铺底，信息靠排版分层，不靠颜色。
- 方正：圆角克制（最大 10px），印章是方的，不用圆形头像。
- 有分量：盖章有落下、压实的动效；按钮按下立刻下沉 1px。

## 2. 颜色

全部 token 定义在 `frontend/src/design/tokens.css`。**组件里禁止出现裸色值**（唯一例外：`WindowControls` 的 Windows 关闭按钮悬停红 `#c42b1c`，这是平台惯例）。

### 六种纸（ADR-0008）

颜色不是一套，而是六套。每种纸都完整定义下表的全部角色，组件只引用角色名，换纸时自动适配。

| 纸 | id | 气质 | 昼夜 |
|---|---|---|---|
| 宣纸 | `xuan` | 暖白，安静（默认） | 白昼 |
| 素笺 | `su` | 中性的白，不偏冷暖 | 白昼 |
| 麻纸 | `ma` | 黄褐粗纸，纤维感重，低眩光 | 白昼 |
| 青笺 | `qing` | 冷灰带青 | 白昼 |
| 夜读 | `ye` | 灯下的深色纸，暖黑 | 夜间 |
| 乌金 | `wujin` | 墨锭的冷黑，带一点青 | 夜间 |

纸由 `data-paper` 属性选择，可以挂在任意元素上：根元素决定全局，设置页的纸样卡片在自己身上挂另一种纸来预览。

新增一种纸的要求：完整复制一块变量重新校准，并运行 `scripts/check-contrast.py`；正文 `--ink` 对 `--paper` 对比度 ≥ 12:1，`--ink-3` ≥ 3.5:1，`--cinnabar` 对 `--paper` ≥ 4.5:1；六种颜料在该纸上彼此可辨。

| 角色 | Token | 用途 |
|---|---|---|
| 纸 | `--paper` / `--paper-raised` / `--paper-sunk` / `--paper-deep` | 消息区 / 浮起的纸（输入框、纪要、卡片、对话框）/ 侧栏 / 侧栏悬停 |
| 墨 | `--ink` → `--ink-4` | 正文 / 次要 / 铅笔灰（元信息、AI 建议）/ 占位与禁用 |
| 线 | `--rule` / `--rule-strong` | 发丝分隔线 / 输入框边、强调分隔 |
| 朱 | `--cinnabar` 系列 | **只属于用户**，见下 |
| 颜料 | `--pigment-*` | AI 成员身份色，每位成员一种 |
| 功能 | `--marker` / `--error` | 荧光笔定位高亮 / 错误 |

### 朱色纪律（最重要的一条）

朱色 `--cinnabar` 只能用于：
1. 用户自己（"我"的印章、用户发言里的 @ 提及）
2. 确认：「定」印、"盖章"按钮、"你确认于"
3. 发送按钮（用户的主动作）
4. 焦点环、串行顺序编号

**不能用于**：装饰、AI 相关的任何元素、错误提示（用 `--error`）、普通链接、警告、徽标。朱色一旦泛滥，"盖章"就失去分量。

### 成员颜料

六种矿物颜料：石青 `shiqing`、石绿 `shilv`、赭石 `zheshi`、藤黄 `tenghuang`、黛 `dai`、紫檀 `zise`。新建成员时按"群里还没用过的"自动分配，用户可改。不再增加新颜色；超过六位成员时允许重复。

成员颜料出现在：印章底色、消息里的名字颜色、流式输出的笔尖、思考中的点。**不出现在**大面积背景上。

## 3. 字体

全部随应用打包（`@fontsource-variable/*`），不依赖系统字体。Windows 上的微软雅黑和 mac 上的苹方观感差别太大，依赖系统字体就谈不上统一风格。

| Token | 字体 | 用于 |
|---|---|---|
| `--font-serif` | 思源宋体 Noto Serif SC | 群名、成员名、区块标题（"决定""待办"）、印章字、对话框标题 |
| `--font-sans` | 思源黑体 Noto Sans SC | 正文、界面文字 |
| `--font-mono` | JetBrains Mono | 编号（#12、M3）、时间、模型名、快捷键、代码 |

规则：
- 聊天正文 15px、行高 1.78，最大行宽 `--reading-width`（720px）。
- 宋体只用于"标题性"的短文本，不用于大段正文（Windows 低分屏上小字号宋体发虚）。
- 区块标题用宋体并加字距（`letter-spacing: .12em–.24em`），这是"纪要"感的来源。
- 中文不用斜体。

## 4. 记忆的三种笔迹（产品灵魂）

纪要条目的左侧有一道笔迹，**这套区分不得改动、合并或省略**：

| 状态 | 笔迹 | 文字 | 元信息 |
|---|---|---|---|
| AI 建议（`proposed` + `origin=member`） | 2px **虚线** `--ink-4`（铅笔） | `--ink-2` | "{成员} 建议" |
| 你提出（`proposed` + `origin=user`） | 2px **实线** `--ink-3`（墨笔） | `--ink` | "你提出 · 待盖章" |
| 已确认（`confirmed`） | 2px 实线 `--cinnabar`（朱笔）+ 右上「定」印 | `--ink` 中粗 | "你确认于 HH:mm"（朱色） |
| 已否决 / 已完成 | 无笔迹，删除线，收进"已完成与已否决" | `--ink-3` | — |

「定」印是**朱文印**（朱色边框 + 朱色字，纸色底），与 AI 成员的**白文印**（颜料底 + 纸色字）形成对照。盖章动画 `stamp-in`：从 1.9 倍大、旋转 -14° 落下，回弹到 -6°，同时一圈墨晕散开。只在用户刚点击时播放一次，刷新后静态显示。

来源编号（#12）悬停时，聊天区对应消息加荧光笔底色；点击时滚动过去并闪烁。这条双向链接是"标明来源"的视觉兑现，不能去掉。

## 5. 印章头像

- AI 成员：方形印章，圆角为边长的 16%，颜料底，宋体粗体单字（默认取名字首字），内有一圈纸色细框（篆刻边栏），叠一层极淡噪点（印泥颗粒）。
- 用户：**私印**（见下）。
- 尺寸：`xs 18 / sm 24 / md 32 / lg 40 / xl 64`。消息用 md，列表用 xs，成员卡片用 xl。
- 状态：排队中去色（`muted`）；思考中轻微呼吸（`active`）。
- 用户上传图片头像时，图片填满同样的方形（`object-fit: cover`），保留圆角，不加内框和颗粒。**动图始终播放，不做限制**（ADR-0008）。
- 头像作用范围是"默认 + 群内覆盖"：所有显示成员头像的地方都通过 `avatarOf(member, group)` 取值，不要直接读 `member.avatar`。
- **不得**改成圆形，不得加渐变、描边阴影或在线状态点。

### 私印

用户刻的 1–4 字印，白文（朱底纸色字，带内框）或朱文（纸底朱色字、朱色边框）。章法：从右往左、从上往下读——
1 字居中；2 字左右并排、字身纵向拉长；3 字右列首字拉长、左列上下两字；4 字田字格（右上→右下→左上→左下）。
小于等于 24px 时多字印只显示首字。

私印是用户在群里的头像，也是确认纪要时盖的印。用户没刻过时（"我" + 白文），确认印仍是朱文「定」。私印只能用朱色，这与"朱色只属于用户"一致。

## 6. 版式与布局

三栏：侧栏 248px（`--paper-sunk`）｜消息区自适应（`--paper` + 纸纹）｜纪要 340px（`--paper-raised` + 纸纹，可收起）。

- 栏与栏之间只用 1px `--rule` 分隔，不用阴影。
- 顶部 64px 是标题行，整行可拖动窗口（加 `.drag` 类）；其中的按钮自动排除。
- macOS：侧栏顶部左侧留 84px 给红绿灯。Windows / Linux：右上角是自绘的窗口按钮（46×32），最右侧标题行需要给它让位（`--edge-right`），或者像纪要面板那样让工具按钮沉到下方。
- 消息不是气泡。采用"手稿"版式：左侧 44px 栏放印章，右侧是名字行和正文。同一轮次（一次发送及其所有回复）的印章之间用 1px 竖线串起来。
- 系统消息居中，两侧发丝线，12px `--ink-3`。
- 间距只用 4px 栅格 token（`--space-*`）。

## 7. 动效与反馈

| 场景 | 规则 |
|---|---|
| 按下 | 所有可点元素 `:active` 时 `translateY(1px)` 或 `scale(.985)`，过渡时长 0（立即响应） |
| 悬停 | 背景/颜色变化 `--dur-quick`（140ms） |
| 入场 | 新消息、菜单、面板 `--dur-base`–`--dur-slow`，`--ease-out`，位移不超过 12px |
| 盖章 | `--dur-stamp` + `--ease-stamp`（带回弹） |
| 流式 | 笔尖 `brush-blink`（900ms 阶跃闪烁），颜色取成员颜料 |
| 定位 | 荧光笔 `marker-flash`（1.6s 淡出） |

- **乐观更新**：盖章、否决、改写在点击瞬间就改界面，后端返回后再校正。不允许出现"点了没反应、等一会儿才变"。
- 流式增量按帧合并（`requestAnimationFrame`），一帧只渲染一次。
- 必须尊重 `prefers-reduced-motion`（token 已处理，组件不要写死时长）。
- 打开一个群时已有的消息**不播放**入场动画，只有新出现的消息播放。

## 8. 夜间纸

夜读与乌金不是反色，是"深色的纸"：底色压暗，朱和颜料都提亮以保证对比。所有颜色都走 token，组件里不需要为夜间单独写样式；如果需要，说明用了裸色值，应改用 token。

## 8.1 阅读偏好

- 正文字号：`data-font="s|m|l"` → `--text-body` 14 / 15 / 17px（大字号时行宽放宽到 760px）。只影响正文，不影响界面文字。
- 排版密度：`data-density="compact"` → 消息上下留白 `--msg-pad` 从 12px 收到 4px，行距从 1.78 收到 1.62。
- 新写的消息类组件，上下留白一律用 `--msg-pad`，正文字号用 `--text-body`，这样会自动跟随偏好。

## 9. 文案

- 用"你"称呼用户，不用"您"。
- 动作用动词："盖章""否决""改写""整理""重新生成"。不用"提交""操作"这类空词。
- 状态说人话："排队中，等 墨白 说完""正在读群记录""已中断"。
- 错误要给原因和出路："401 Unauthorized：该模型服务的 API Key 无效" + "重试"按钮。
- 不用感叹号，不用 emoji，不用"智能""赋能"。

## 10. 组件清单（只能用这些拼页面）

`Button`（primary / accent / ghost / quiet）、`Segmented`、`Dialog`、`Field` + `TextInput` / `TextArea`、`Seal` / `UserSeal`、`Icon`。
业务组件可复用：`AvatarEditor`（头像编辑，支持群内与默认两种范围）。

新页面照着现有页面写：
- 表单对话框 → `features/rail/CreateGroupDialog.tsx`
- 列表 / 卡片页 → `features/members/MembersView.tsx`
- 设置类分节页 → `features/settings/SettingsView.tsx`
- 需要新组件时，先在任务单写明用途与草图，交项目所有者确认后再做。**禁止引入 UI 组件库**（MUI、Ant Design、shadcn 等）和图标库。

## 11. 跨平台验收

每个涉及界面的任务，都要在以下环境确认无误后才算完成（没有真机时用 `?platform=windows` 预览布局，并在任务单注明"未真机验证"）：
- macOS（WebKit）、Windows 10 与 11（WebView2 / Chromium）、Ubuntu（WebKitGTK）
- 六种纸（至少：宣纸、麻纸、夜读、乌金），以及紧凑密度 + 大字号的组合
- 窗口最小尺寸 960×640
- 中文输入法：组字过程中按 Enter 不能发送
