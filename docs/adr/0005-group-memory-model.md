# ADR-0005 群记忆：条目化、带来源、只有用户能确认

- 状态：已采纳（2026-10-15）

## 决定
1. 记忆以群为单位，AI 没有个人记忆。成员进入哪个群，提示词里就只有哪个群的记忆。
2. 记忆由**条目**组成：类型（背景/方案/决定/待办）、一句话内容、状态（proposed/confirmed/rejected/done/superseded）、来源（origin=user|member）、提出者、来源消息编号列表。
3. 状态与来源正交：用户在聊天里说"就这么定"，会被整理成 origin=user、status=proposed，仍需用户在界面上盖章才成为 confirmed。
4. 整理模型只输出 JSON 操作，由 `memory.Apply` 校验：
   - 不能产生 confirmed；不能修改、取代、完成 confirmed 条目
   - 每条必须引用本次窗口内存在的消息
   - origin=user 必须有用户消息作来源，否则降级为 member
   - 完成待办必须有用户消息作证据
5. 已否决的条目保留，并在提示词里列为"不要再提"。
6. 整理游标 `Group.MemoryCursor`：已整理的最后一条消息编号。被裁掉又未整理的消息，提示词里如实告知模型。

## 理由
一段自由文本摘要无法标明来源，也无法区分"谁说的、算不算数"；条目化之后，界面可以逐条盖章，提示词可以逐条标注可信度。

## 后果
- 记忆质量取决于整理提示词（`internal/memory/memory.go` 的 systemPrompt），调整它需要附带真实对话样例的前后对比。
- 用户的盖章、否决、改写都是本地操作，不经过模型。
