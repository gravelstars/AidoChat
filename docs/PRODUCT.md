# 产品范围

## 一句话

本地运行的 AI 群聊：把不同的 AI 像数字员工一样拉进同一个群，用 @ 点名交流；每个群有自己的记录和纪要，AI 进哪个群就只知道哪个群的事。

## 路线：精简

不做大而全。每加一个功能都要回答："它让'群 + @ + 纪要'这个核心更好用了吗？"答不上来就不做。

## 第一版做什么

1. **成员**：名字、印章头像、一句话简介、角色提示词、模型服务与模型。
2. **模型服务**：OpenAI 兼容（覆盖国内大多数厂商、Ollama、OpenAI）与 Anthropic 两类；Key 存系统钥匙串。
3. **群聊**：新建群（名称、主题、成员、默认回复方式），邀请/移出成员，改名，归档。
4. **@ 交流**：@单人、@多人、@所有人；多人时可选依次或同时回复；没有 @ 的消息只记录不回复；停止、重试。
5. **群纪要**：自动整理背景、方案、决定、待办；标明来源；AI 建议与用户确认分开；用户盖章、否决、改写。
6. **本地持久化**：重启后继续讨论。
7. **日间 / 夜读**两套主题；Windows、macOS、Linux 三平台。

## 明确不做（第一版）

| 不做 | 原因 |
|---|---|
| AI 主动 @ 其他 AI、AI 之间自动对话 | ADR-0001：只有用户能触发回复，行为可控 |
| AI 的个人记忆、跨群记忆 | 记忆以群为单位，这是产品定义 |
| 工具调用、联网搜索、执行代码 | 会把产品拖向"Agent 平台"，偏离核心 |
| 文件 / 图片上传 | 第二版再评估 |
| 多用户、账号、云同步 | 本地单用户应用 |
| 插件系统、提示词市场 | 大而全路线 |
| 语音 | 同上 |

## 隐私说明（界面中必须如实告知）

- 数据保存在本机。
- 调用云端模型时，被 @ 成员的上下文（群规则、群纪要、近期聊天记录）会发送给该成员配置的模型服务。
- 整理纪要时，新的讨论会发送给"整理模型"所在的服务。
